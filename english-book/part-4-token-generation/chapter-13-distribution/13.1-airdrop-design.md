# 13.1 Airdrop Design and Execution

The airdrop is the primary mechanism for achieving broad initial token distribution. A well-designed airdrop simultaneously rewards early users, creates broad ownership, generates awareness, and establishes initial market liquidity.

{% hint style="info" %}
**Learning Objectives**

After completing this section, you will be able to:
- Design eligibility criteria that balance rewarding genuine users with practical constraints
- Select and combine distribution formula components (base, tier, duration, value)
- Implement anti-Sybil measures to prevent multi-wallet gaming
- Plan operational execution including snapshot, claims, and deadlines
{% endhint %}

---

## 13.1.1 Airdrop Strategy Framework

### Eligibility Criteria

The criteria must balance rewarding genuine users with practical implementation:

| Criteria Type | What It Targets | Risk |
|--------------|----------------|------|
| **Activity-based** | Users with minimum transactions, deposits, or engagement duration | May exclude new users |
| **Value-based** | Users who contributed minimum TVL, volume, or fees | Creates wealth bias |
| **Loyalty-based** | Users active through adverse conditions (bear markets) | Small eligible pool |
| **Cross-ecosystem** | Users of related protocols or ecosystems | May include non-genuine participants |

**Recommended approach:** Combine multiple criteria types to create a holistic eligibility framework that captures different dimensions of genuine engagement.

### Anti-Sybil Measures

Regardless of criteria, Sybil detection is essential:

- **Minimum transaction thresholds** — flag wallets with only small, gas-minimizing transactions
- **Behavioral analysis** — cluster wallets transacting identically in timing and pattern
- **Gitcoin Passport** or similar identity solutions — score reflecting unique human likelihood
- **Graph analysis** — on-chain transaction patterns identifying related wallets

### Distribution Formula

| Component | Description | Effect |
|-----------|-------------|--------|
| **Flat (base)** | Same amount to every eligible wallet | Maximally egalitarian |
| **Tiered** | Grouped by engagement level; higher tiers get more | Rewards commitment |
| **Proportional** | Proportional to a metric (fees paid, TVL) | Rewards economic contribution |
| **Hybrid (recommended)** | Base + tier + proportional with caps | Broad distribution while rewarding top users |

**Recommended formula structure:**
```
Base allocation:       X tokens per eligible address (ensures breadth)
Engagement multiplier: 1.5-3x based on usage intensity tier
Duration bonus:        Y tokens per month of pre-TGE activity
Value bonus:           Z tokens proportional to fees paid (capped to prevent whale domination)
```

## 13.1.2 Case Study: Designing an Airdrop for "LendDAO"

**Protocol context:** Operating 18 months, preparing for TGE.

| Parameter | Value |
|-----------|-------|
| Total supply | 1 billion LEND |
| Airdrop allocation | 8% (80 million LEND) |
| Total unique users | 45,000 wallets |
| Likely Sybil wallets | 5,000 (flagged by Gitcoin Passport + behavioral analysis) |
| **Eligible after filtering** | **40,000 wallets** |

### User Segmentation

| Tier | Criteria | Wallets |
|------|----------|---------|
| **Tier 1 — Whale Users** | >$100K deposited, >12 months active | 500 |
| **Tier 2 — Power Users** | $10K-$100K deposited, >6 months active | 3,000 |
| **Tier 3 — Regular Users** | $1K-$10K deposited, >3 months active | 12,000 |
| **Tier 4 — Casual Users** | <$1K deposited or <3 months active | 24,500 |

### Distribution Calculation

**Base allocation:** 500 LEND per eligible address
```
40,000 x 500 = 20M LEND (25% of airdrop)
```

**Tier multiplier:** (Tier 1: 8x, Tier 2: 4x, Tier 3: 2x, Tier 4: 1x base)
```
Tier 1: 500 x 8 = 4,000 LEND x 500 wallets  =  2.00M LEND
Tier 2: 500 x 4 = 2,000 LEND x 3,000 wallets =  6.00M LEND
Tier 3: 500 x 2 = 1,000 LEND x 12,000 wallets = 12.00M LEND
Tier 4: 500 x 1 = 500 LEND x 24,500 wallets   = 12.25M LEND
                                          Total:  32.25M LEND
```

**Duration bonus:** 100 LEND per active month, capped at 1,800 (18 months)
```
Estimated total: ~15M LEND
```

**Value bonus:** Proportional to fees paid, capped at 10,000 LEND per wallet
```
Estimated total: ~12.75M LEND
```

**Total: 20M + 32.25M + 15M + 12.75M = 80M LEND**

### Distribution Analysis

| Metric | Value |
|--------|-------|
| Average airdrop per wallet | 2,000 LEND |
| Tier 1 average | ~15,000 LEND (7.5x average) |
| Tier 4 average | ~1,000 LEND (0.5x average) |
| Gini coefficient | ~0.45 (moderate inequality reflecting genuine usage differences) |

{% hint style="success" %}
**This Distribution Achieves:**
- **Broad reach** — 40,000 recipients
- **Proportional reward** — genuine engagement rewarded without extreme concentration
- **Sybil resistance** — filtered + capped bonuses
- **Market formation** — sufficient initial sell pressure for healthy price discovery
{% endhint %}

## 13.1.3 Airdrop Operational Execution

**Snapshot Timing:** Taken before any public announcement to prevent gaming. Best practice: retroactive snapshot (eligibility based on historical activity, announced only at TGE).

**Claim Mechanism:** Purpose-built web interface. The claim contract must be audited; interface hosted on the official domain with clear security communications to prevent phishing.

**Claim Deadline:** 90-180 days. Unclaimed tokens revert to treasury or are burned.

**Tax Considerations:** In many jurisdictions, airdropped tokens constitute taxable income at receipt. Provide recipients with fair market value documentation at time of claim.

---

## Key Takeaways

- Combine multiple eligibility criteria types for holistic genuine-user targeting
- Anti-Sybil measures (behavioral analysis, Gitcoin Passport, graph analysis) are non-negotiable
- Hybrid distribution formula (base + tier + duration + capped value) achieves breadth and proportionality
- Target a Gini coefficient of 0.3-0.5 for the airdrop distribution (moderate inequality)
- Retroactive snapshot prevents gaming; claim deadlines prevent perpetual token float
- The LendDAO case study provides a replicable template for airdrop design
