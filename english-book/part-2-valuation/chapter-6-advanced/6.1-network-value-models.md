# 6.1 Network Value Models

Some protocols derive their value primarily from **network effects** rather than direct cash flow generation. For these protocols, network value models provide an important complementary valuation approach.

## 6.1.1 Metcalfe's Law and Token Valuation

### The Law

**Metcalfe's Law** states that the value of a network is proportional to the square of the number of connected users:

```
V ∝ n²
```

Where:
- V = Network value
- n = Number of network participants

### Theoretical Foundation

The logic: If a network has *n* users, the number of potential connections is approximately n(n-1)/2, which grows quadratically with n. Each connection has value, so total network value grows with the square of users.

### Empirical Research

**Alabi (2017):** Found that Bitcoin and Ethereum market values were reasonably well-explained by Metcalfe's Law using daily active addresses as the network size metric.

**Peterson (2018):** Extended this analysis and found that a **generalized Metcalfe model** (V ∝ n^1.5, a modified exponent) provided the best fit for Bitcoin's historical valuation.

{% hint style="info" %}
**Modified Exponents**

Research suggests the pure quadratic relationship (n²) may be too strong. Modified exponents between 1.5 and 2.0 often provide better empirical fits:

- **n^1.5:** Best fit for Bitcoin (Peterson)
- **n^1.7:** Good fit for social networks
- **n^2.0:** Theoretical Metcalfe maximum
{% endhint %}

### Practical Application Framework

**Step 1: Historical Regression**

Regress historical token price against network size metrics:
- Daily active addresses
- Weekly active addresses
- Unique wallet addresses
- Transaction count

```
ln(Price) = α + β × ln(Active Addresses) + ε
```

The coefficient β tells you the elasticity—if β ≈ 2, Metcalfe's Law holds; if β ≈ 1.5, a modified version applies.

**Step 2: Network Growth Projection**

Project future network growth based on:
- User acquisition trends
- Market penetration estimates
- Competitive dynamics
- Ecosystem development roadmap

**Step 3: Value Projection**

Apply the estimated relationship to project future token value:

```
Future Value = Current Value × (Future Users / Current Users)^β
```

### Example: Layer 1 Protocol Valuation

**Current metrics:**
- Market cap: $5 billion
- Daily active addresses: 100,000
- Historical β (elasticity): 1.6

**Projected growth:**
- Daily active addresses in 3 years: 400,000 (4x growth)

**Value projection:**
```
Future Value = $5B × (400,000 / 100,000)^1.6
             = $5B × 4^1.6
             = $5B × 9.19
             = $45.95 billion
```

**Implied CAGR:** 109% per year

{% hint style="warning" %}
**Reality Check Required**

Network growth projections must be realistic. A 4x increase in active users over 3 years is aggressive and requires:
- Clear user acquisition strategy
- Competitive advantages
- Market expansion opportunity
- Ecosystem development

Always sanity-check network projections against comparable protocol growth rates.
{% endhint %}

## 6.1.2 Limitations of Metcalfe's Law for Protocols

Metcalfe's Law is **best suited for:**
- **Layer 1 blockchains** (Bitcoin, Ethereum, Solana)
- **Layer 2 networks**
- **Communication protocols** where primary value is connecting participants

Metcalfe's Law is **less appropriate for:**
- **Application-layer protocols** (DEXs, lending markets)
- **Protocols with direct revenue models**
- **Protocols where users don't interact with each other**

{% hint style="success" %}
**When to Use Network Models**

Use network value models for protocols where:
1. Network effects are the primary value driver
2. User growth is measurable and predictable
3. Users interact with each other (not just with the protocol)
4. Cash flows are minimal or difficult to project

For application-layer protocols, **direct cash flow valuation** is generally more appropriate, with network effects captured through growth rate assumptions.
{% endhint %}

## 6.1.3 NVT Ratio (Network Value to Transactions)

### Definition

The **NVT Ratio**, proposed by Willy Woo in 2017, is the crypto analog of the P/E ratio:

```
NVT = Network Value (Market Cap) / Daily Transaction Volume (USD)
```

Or annualized:
```
NVT = Market Cap / (Daily Transaction Volume × 365)
```

### Interpretation

**High NVT:** Network is overvalued relative to transaction activity (or investors are pricing in future growth)

**Low NVT:** Network is undervalued, or being used primarily for transactions rather than store of value

### NVT Signal

A **smoothed variant** using 90-day moving average of transaction volume:

```
NVT Signal = Market Cap / MA90(Daily Transaction Volume × 365)
```

**Research finding:** NVT Signal is a useful indicator of market cycle positioning:
- **High NVT Signal** → Correlates with market tops
- **Low NVT Signal** → Correlates with market bottoms

### Protocol-Specific NVT Application

For protocol-specific valuation, calculate NVT using **protocol-specific transaction volume**:

**DEX protocol:**
```
NVT = Market Cap / Annual Trading Volume
```

**Lending protocol:**
```
NVT = Market Cap / Annual Lending Volume
```

This provides a protocol-specific valuation signal that can be:
- Compared across peers
- Tracked over time
- Used to identify relative over/undervaluation

### Example: DEX Protocol NVT Analysis

**Protocol A:**
- Market cap: $800M
- Annual trading volume: $50B
- NVT: 0.016

**Protocol B:**
- Market cap: $600M
- Annual trading volume: $20B
- NVT: 0.030

**Interpretation:** Protocol B has a higher NVT—either it's overvalued relative to its transaction activity, or the market expects Protocol B to grow faster than Protocol A.

{% hint style="info" %}
**Using NVT in Comparable Analysis**

NVT ratios help identify which protocols in a peer group are trading at premium or discount valuations relative to their transaction activity. Combine with revenue multiples for comprehensive analysis.
{% endhint %}

## 6.1.4 The Token Velocity Problem

### Quantity Theory of Money for Tokens

The **Quantity Theory of Money** (MV = PQ) has been adapted to token valuation by Chris Burniske:

```
M × V = P × Q
```

Where:
- **M** = Token market capitalization (money supply)
- **V** = Token velocity (how quickly tokens change hands)
- **P** = Price of the digital resource
- **Q** = Quantity of the digital resource provisioned

Rearranging:
```
M = PQ / V
```

### The Velocity Problem

For a given level of economic activity (PQ), **higher token velocity reduces required token market cap**.

**Implication:** If tokens circulate rapidly (high V), each token does not need to be worth very much to support a given level of economic activity.

**Example:**
- Protocol has $1B annual transaction volume (PQ)
- Token velocity = 10 (each token used 10x per year)
- Required market cap: $1B / 10 = $100M

If velocity increases to 20:
- Required market cap: $1B / 20 = $50M

**Token price drops by 50% even though economic activity is unchanged!**

### Implications for Token Design

Tokens with mechanisms that **reduce velocity** should command higher valuations:

1. **Staking requirements** - Lock tokens to participate in consensus
2. **Lock-up periods** - ve-tokenomics (vote-escrow model)
3. **Governance participation incentives** - Reward long-term holding
4. **Utility requirements** - Must hold tokens to access services
5. **Yield generation** - Tokens earn yield when held

{% hint style="success" %}
**The ve-Tokenomics Solution**

The **ve (vote-escrow) model** pioneered by Curve is an economic justification for higher valuations:

By locking tokens for extended periods (up to 4 years), velocity is dramatically reduced, and the required market cap for a given level of economic activity increases.

**Example:**
- Average lock period: 2 years
- Effective velocity: ~0.5 (tokens turn over every 2 years)
- Required market cap increases by 20x vs. velocity of 10
{% endhint %}

## 6.1.5 Practical Valuation Using Velocity

### Framework for Utility Token Valuation

For a **utility token** (consumed or staked to access protocol services):

**Step 1: Estimate Annual Economic Throughput**
```
PQ = Annual fees paid, service volume, transaction value
```

**Step 2: Estimate Token Velocity**

Based on:
- On-chain data (how frequently tokens change wallets)
- Comparable protocols with similar token mechanics
- Staking/lock-up participation rates

**Step 3: Calculate Implied Market Cap**
```
M = PQ / V
```

**Step 4: Per-Token Value**
```
Token Value = M / Circulating Supply
```

### Example: Data Oracle Network

**Assumptions:**
- Annual data request value: $500M (PQ)
- Oracle token has velocity of 5 (each token used 5x/year)
- Circulating supply: 1 billion tokens

**Calculation:**
```
Implied market cap = $500M / 5 = $100M
Per-token value = $100M / 1B = $0.10
```

**Sensitivity to velocity:**

| Velocity | Market Cap | Per-Token Value |
|----------|------------|-----------------|
| 2 | $250M | $0.25 |
| 5 | $100M | $0.10 |
| 10 | $50M | $0.05 |
| 20 | $25M | $0.025 |

{% hint style="warning" %}
**Velocity Is Hard to Predict**

Token velocity is one of the most difficult parameters to estimate:
- User behavior changes over time
- Token mechanics evolve
- Market conditions affect holding patterns

Always run sensitivity analysis across velocity assumptions. Small changes in velocity can have large impacts on valuation.
{% endhint %}

## 6.1.6 Combining Network Models with Cash Flow Analysis

Best practice: **Use network models as a complement** to cash flow analysis, not a replacement.

### Integrated Framework

1. **Base case:** DCF valuation using projected cash flows
2. **Network validation:** Check if implied growth rates are consistent with network growth projections
3. **Relative valuation:** Use NVT to assess valuation vs. peers
4. **Velocity analysis:** Ensure token velocity assumptions are realistic

If network models and cash flow models diverge significantly, investigate:
- Are growth assumptions too aggressive/conservative?
- Is revenue monetization improving/declining?
- Are network effects being properly captured in cash flow projections?

## Key Takeaways

1. **Metcalfe's Law applies best to infrastructure protocols** where network effects dominate value creation
2. **Modified exponents (1.5-1.7) fit better empirically** than pure quadratic (2.0)
3. **NVT ratio is crypto's P/E analog** - High NVT suggests overvaluation or growth expectations
4. **Token velocity problem is fundamental** - High velocity destroys token value
5. **ve-tokenomics and staking reduce velocity** - Justifies higher valuations
6. **Network models complement DCF** - Use both for comprehensive analysis
